# 批量采集：宿主内悬浮面板（2026-11-22 用户指定版式）

面板注入在小红书当前页的 decorView 上（与「采集/取消」按钮同一套注入逻辑），
**采集中显示、翻页跟随、收工后保留 4 秒**。不拦截触摸（面板 isClickable=false）。

## 版式

```
┌──────────────────────────────────────┐  ← 宽 = 屏宽 62%，高 = 150dp
│ 采集中 · 已处理 12 篇 · 已存 9 · 失败 2 │  ← 顶栏第一行（粗体 12.5sp，常驻不滚）
│ 待处理 6 · 用时 4:12                  │  ← 顶栏第二行（每秒刷新）
│ ──────────────────────────────────── │  ← 1px 分隔线
│ 12:43:03 点开第 3/5 张（noteId=6a1d…） │  ← 过程消息，最近 6 条
│ 12:43:04 已下载过，跳过                │     自动滚到底（ScrollView）
│ 12:43:05 解析不出图片（RequiresWeb…)   │
└──────────────────────────────────────┘
   半透明黑 0xB3000000，圆角 10dp，左下角，leftMargin 14dp / bottomMargin 120dp
```

## 字段含义

| 字段 | 来源 | 说明 |
|---|---|---|
| 状态 | `XhsBatchDriver.header()` | 采集中 / 收尾中（点了取消）/ 已结束 |
| 已处理 N 篇 | `processed` | 成功 + 跳过，即「走完的笔记数」 |
| 已存 N | `okCount` | 真正落盘成功的**篇数**（不是图片张数） |
| 失败 N | `failedCount` | 解析失败（含 RequiresWebView 这类数据源限制）、点不动 |
| 待处理 N | `cards.size - index` | **本屏**还剩几张没走（不是整本主页剩余量，服务端不告诉我们总量） |
| 用时 m:ss | `startedAt` | 从点「采集」起算 |

## 为什么待处理只算本屏

主页是滚动分页加载的，服务端不返回总数，客户端也不知道后面还有多少篇。
面板只能诚实报「当前这一屏还剩几张」，滚一屏后重新计数。
