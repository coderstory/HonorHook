# 先验 Hook 架构师宣言（哲学表述版）

> 2026-10-09 定稿。用康德先验框架对"开发 LSPosed Hook 插件"的纯粹理性批判。
> 与 `CLAUDE.md §九`（工程条款版）一一对应：先验时空→边界优先/生命周期、因果锚点→稳定锚点/找决策不找表象、先验律令→最小侵入/防御性/可降级、现象界适配→抽象适配层。两版互为表里：工程版供逐条对照评审，本版供架构判断力的内化。

**目标应用/系统组件**：Android 运行时（ART）及目标应用的现象界
**目标 Android 版本**：跨版本（现象界的流变）
**功能描述**：开发者（先验主体）通过模块（立法工具），对目标应用（认知客体）进行行为重构。

## 1. 先验时空分析：立法的边界

开发 Hook 插件的第一步，不是写代码，而是划定时空。

- **空间（作用域）**：必须在 AndroidManifest 和 LSPosed Manager 中预先声明模块将侵入哪些包的哪些进程。这不是配置，这是领海宣言——没有这个边界，代码就是公海上的海盗，随时会被系统击沉。
- **时间（生命周期）**：必须选择 `handleLoadPackage` / `Application.attachBaseContext` 这样的时间锚点。在类加载之前或之中介入，才是在"时间"这个直观形式中合法存在。

## 2. 因果锚点选择：寻找现象界的"物自体"入口

写的每一行 Hook 代码，都是在寻找目标应用逻辑中的因果律。

- **寻找决策点**：要修改一个功能，必须找到那个"做出决定的方法"（如 `isAdEnabled()`、`checkSignature()`）。这是现象界中稳定的"实体范畴"。
- **拒绝表象**：如果去 Hook 一个 `TextView.setText()` 来去广告，就是在对抗现象界的流变（UI 随时改），而不是在利用因果律——这违背了先验范畴的稳定性要求。

## 3. 先验律令审查：方法论的纯粹理性

开发过程必须接受以下律令的审判：

- **最小侵入律**：Hook 回调中只做接线，重逻辑外移。这是"质"的范畴——不能让修改的体量超过原方法本身的承载力。
- **防御性律**：try-catch 不是可选项，是道德律。异常绝不能污染客体的现象界，否则就是"二律背反"（模块崩溃导致宿主崩溃）。
- **可降级律**：每个功能必须有开关。这是"可能性"的范畴——让修改行为在逻辑上可以撤销，符合"自由意志"的先验假设。

## 4. 现象界适配：版本碎片化的先验演绎

Android 版本升级，就是现象界的重构。

- 模块（主体）不能改变物自体（应用的核心意图），但必须调整自己的范畴（Hook 点适配），以应对新的现象呈现方式。
- 这就是为什么需要 `if (Build.VERSION.SDK_INT >= ...)`——这是在不同版本的"现象界"中，重新寻找同一"物自体"的认知努力。（工程版补充：**特征检测优于版本号**——按方法签名/类存在性动态判断，比硬编码 SDK_INT 更接近物自体。）

## 5. 结论：先验立法总结

开发 Hook 插件，就是先验主体在 Android 运行时这个现象界中，通过**划定时空边界、寻找因果锚点、遵守纯粹理性的律令**，对目标应用进行的一次"认知重构"。

**模块不是外挂，而是现象界的新秩序。**
