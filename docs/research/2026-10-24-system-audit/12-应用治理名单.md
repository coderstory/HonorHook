## 0. 机制一句话矩阵
| 机制 | 语义 | 取舍 |
|---|---|---|
| `pm disable-user --user 0 <pkg>` | 状态置 DISABLED_USER(3)，可 `pm enable` 恢复 | **首选**；本机临时 root 下落 /data 持久（一次永久生效），但解冻同样需 root 在场——冻结前想清楚 |
| `pm suspend <pkg>` | 挂起（API 24+），应用图标隐藏、不可运行，可 `pm unsuspend` | 适合"软屏蔽"预置三方；需 root/shell 权限，恢复最干净 |
| `pm hide <pkg>` | 隐藏（置 HIDDEN），类似停用但状态位不同 | 兼容性一般，部分 ROM 恢复异常；不如 disable-user 直观 |
| `pm uninstall -k --user 0 <pkg>` | 仅 user 0 卸载，保留 /data 与 APK | 最彻底；恢复需 `pm install-existing`，系统应用可恢复但风险最高，红线包绝不可用 |

## 快照/恢复机制建议（命令草案，仅供后续执行方）
```bash
# 快照：全量包+状态（enabled 0/1/2/3/4）
pm list packages -s | sed 's/package://' | sort > pkgs.txt
for p in $(cat pkgs.txt); do echo "$p $(pm list packages -d | grep -q "package:$p$" && echo disabled || echo ok)"; done > pkg-state-$(date +%F).txt
# 或一次性 dumpsys 快照（更完整，含每个 userId 的 enabled 状态）
dumpsys package > dumpsys-pkg-$(date +%F).txt
# 恢复单个：pm enable <pkg>；恢复卸载：pm install-existing <pkg>；解除挂起：pm unsuspend <pkg>
```
注：本机 root 为临时 root，恢复操作务必确认 root 在场时执行；保活类（云音乐等被 iaware alivekeep 复活者）走「设置→启动管理」关闭，不进冻结名单。
