# 复盘：tamer 移植与页签隐藏的深夜拉锯（2026-11-19）

一次本该几小时收尾的移植，从 22:50 拖到 23:31、装了十几轮包、用户数次愤怒。技术结论已沉淀在
[reverse/appmarket.md](reverse/appmarket.md)（两条装配链、MountEngine `$a` 派发坑、七层拦截）；
本文只复盘**过程错在哪**，给下次的自己立规矩。

## 一、判定「生效」的证据用错了层

**事实**：我在数据链路（g 删表、BO getter 过滤、T0 删 2 项）看到日志就宣布「生效了」，
至少三次。用户每次看到的都是 5 个页签。

**根因**：日志证明的是「我的代码执行了」，不是「用户看到的东西变了」。16.1.11 有两条
互不相关的装配链，拦住一条甚至两条的入参，UI 仍可能从漏网的链路取数。

**规矩**：
- UI 类 hook 的生效判据只有两个——**用户肉眼确认**，或 **sink 层证据**（渲染出口收到过滤后的数据）。
  中间层日志只能证明「执行了」，永远不能证明「够了」。
- 报告生效时必须声明验证层：「t0direct 删 2 项（日志层）」vs「页签 5→3（用户确认）」是两句话。

## 二、探针挤牙膏，而不是一次全上

**事实**：v1 tab 探针 → v2 navprobe/itemviewprobe → v3 前移注册 → v4 inflate → v5 setId →
v6 addView。六轮，每轮一次构建+安装+冷启动+读日志，用户等了十几分钟一次。
用户原话：「你能一次把测试代码全写了吗」「所有的可能性一次性全上」。

**根因**：每轮只验证「我当前最怀疑的那一个假设」。但设备验证的往返成本极高（构建 10s +
弹窗人工确认 + 冷启动 20s + 读日志），假设之间又不互斥。

**规矩**：设备往返成本高时，**一轮上全部候选探针**（栈探针一次打穿调用链），让一次安装回答
所有问题。addView 探针如果第一轮就上，整个排查从 6 轮变 1 轮。

## 三、cleanup 脚本删过头，功能静默丢失

**事实**：清探针时用「注释起点 → `navProbeBound = true`」做删除区间，把同区间内后插入的
ddirect、rotblock 一起删了。构建绿、测试绿，没人发现——rotblock 的丢失只表现为「自动旋转
又被打开了」，而那会被归因成宿主行为。

**规矩**：
- 区间删除必须用**成对锚点**（起止注释），不能用「下一个标志物」当终点。
- 删除后 grep 关键 setId（`ddirect`、`rotblock`）确认存活，再构建。

## 四、安装通道的失败被误读

**事实**：`pm install -r` 需要解锁屏 + 几秒内人工点弹窗；锁屏/超时一律返回
`INSTALL_FAILED_ABORTED: User rejected permissions`。我把多次超时当成「用户拒绝」或反复
盲重试，与用户来回拉扯。

**规矩**：这个错误码在本机语义 = **弹窗没被点到**。正确动作是停下来说明前置条件（解锁、
盯着屏幕），由用户说「装」再发起，而不是自动重试。

## 五、「是不是我干的」要有实验，不能只有否认

**事实**：用户指控测试打开自动旋转。我先否认（「我全程没碰设置」），后来实测
「值 0 → 冷启动市场 → 12s 后变 1」才坐实是市场进程写的——但我的每次测试都在冷启动市场，
所以**用户观察「每次你测试就会开启」完全正确**，错的只是归因对象。

**规矩**：被指控时第一步做对照实验（不启动市场，设置变不变？），数据出来再说话。
用户的因果观察通常比我的直觉可信。

## 六、直挂与 pending 表的分界没有及早固化

**事实**：`$a` 类方法的 MountEngine 挂载显示成功但 intercept 从不执行（tab.d、tab.t0 双证实）。
这个坑第一次出现（tab.t0，22:28）就该被抽象成规则并全量排查同类任务，而不是每条链路
各自撞一次墙。

**规矩**：发现「挂载成功但回调零日志」的系统性异常后，立即对全部 pending 任务做一次
「是否真的在跑」普查（每分支加一行进入日志），而不是逐个排查。
