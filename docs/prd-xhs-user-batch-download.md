# PRD — 工具箱「小红书用户作品批量下载」

> 状态：草案 v1（待评审）
> 归属模块：HonorHook UI 侧工具箱（`ui/screen/ToolboxScreen.kt` Hub 新增入口 + 新二级页）
> 复用资产：上游 XHS_Downloader_Android 管线（`com.neoruaa.xhsdn.*`，AGPL-3.0，经 7 文件白名单进 `libs/xhs-dn-core`）

## 1. 背景与目标

现有 XHS 能力只有「分享链接 → 单篇解析 → 外挂直下」（`XhsSavePivot` / `XhsBatchSave`）。用户需要**按作者维度**批量搬运：输入一个小红书用户 ID（如 `1504334302`），拉取该用户的笔记列表，逐篇解析其中的图片与视频并批量下载，全部落在以该用户 ID 命名的新建文件夹里。

**目标**：一次输入、无人值守、串行安全（不触发风控）、进度可见、随时可退（含物理撤回已下载文件）。

**非目标（v1 不做）**
- 不做收藏 / 点赞 / 合集等其它维度的批量
- 不做断点续传（任务取消后再来 = 重新整跑；已有文件按 URL 去重跳过即可）
- 不做并发 / 多任务并行（风控红线，见 §4）
- 不做登录态下载（仅公开可见内容；私密/仅粉丝可见笔记直接跳过并计数）

## 2. 用户流程

```
工具箱 Hub → [小红书批量下载] 入口
  → 二级页：输入用户 ID → [开始]
  → 运行页：进度面板（§5）+ [暂停] [取消] [撤回]
  → 完成：汇总（文章/图片/视频/MB）+ 文件夹路径 + [撤回] 仍可用
```

- 输入校验：纯数字用户 ID（去掉首尾空白）；非法输入不启动。
- 目录：`<既有下载根目录>/<用户ID>/`，开始任务时创建；所有媒体文件**平铺**在该目录（不建笔记子目录）。文件名用 `<笔记ID>-<原名/序号>` 防跨篇重名冲突。
- 结束后任务记录（用户 ID、计数、路径）保留在页面内，直到用户离开页面。

## 4. 技术方案与约束

### 4.1 数据来源（关键风险 → 已有解法）

上游 `XhsContentRepository.resolve()` 只支持**分享链接 → 单篇 HTML 解析**，**没有**用户维度列表能力。用户笔记列表 v1 主路线 = **离屏（headless）WebView**：

1. 在离屏 WebView 里加载 `https://www.xiaohongshu.com/user/profile/<用户ID>`；页面自身 JS 负责算 `x-s` / `x-t` 签名并发 edith 请求——**我们不碰签名**。
2. `shouldInterceptRequest` 拦截 `/api/sns/web/v1/user_posted` 响应，取 JSON 里的笔记列表与 `cursor`；向页面注入滚动（JS evaluate）触发加载更多，直到 `has_more=false` 或达到篇数上限。
3. 兜底：若 WebView 路线失败（页面改版/拦截失灵），回落抓 profile 页 HTML 解析 `__INITIAL_STATE__`（首屏约 20 篇，免签名）。
4. 登录态（可选增强）：照搬上游 `SessionCredentials` + `CookieManager` 的 cookie 捕获路子（`WebViewActivity` 同款），登录后可见范围更大、风控更松；未登录时仅公开内容。

**注意**：headless WebView 全程无头、不弹 UI；滚动节奏并入 §4.2 串行节流（翻页间隔同样 2-4s）。WebView 内页面自身发起的请求由页面 JS 控制，节流以「注入滚动的频率」为闸门。

> 每**篇**笔记的媒体解析仍走上游既有 HTML 解析（单篇链接，OkHttp 带 cookie/UA 直接 GET），这条链路已实证可用。整条链路零 hook 依赖。

### 4.2 串行与节奏（风控）

- 全任务**单协程串行**：拉列表 → 逐篇解析 → 逐文件下载，同一时刻仅 1 个 HTTP 连接。
- 请求间加固定随机间隔（列表/解析页 ~2-4s，媒体文件 ~0.5-1.5s；实现时抽成常量表）。
- 无 DNS/连接复用层面的并发池；OkHttp client 全任务共用 1 个实例但 `maxRequests=1`。

### 4.3 状态机

```
Idle → Fetching(列表) → Running(逐篇) ⇄ Paused → Done | Cancelled | Withdrawn
                                   ↘ Error(重试耗尽)
```

- 状态持有：UI 侧 `ViewModel`（本功能纯 UI 侧，不涉 hook，不需要 `FeatureCatalog` 开关——但若要求可关闭，仍按纪律在 `FeatureCatalog` 加 key）。
- 撤回 = `cancel()` + 删除 `<用户ID>/` 目录；删除前弹确认；删除结果（成功/失败 N 个文件）回显。

### 4.4 进度模型

```kotlin
data class BatchProgress(
    val userId: String,
    val notesFound: Int,      // 抓到的文章数
    val notesProcessed: Int,  // 已处理（成功+失败+跳过）
    val notesFailed: Int,
    val imagesDone: Int,
    val videosDone: Int,
    val totalBytes: Long,     // 累计 MB = totalBytes/1MB，面板保留 1 位小数
    val state: State,
)
```

MB 统计按**落盘字节数**计（读文件长度累加），不做预估值。

## 5. 界面细节

- 输入页：一个输入框（label「小红书用户 ID」）+ [开始] 按钮 + 一行风险提示文案（「串行下载，请勿频繁操作；仅下载公开内容」）。
- 运行页（进度面板，从上到下）：
  - 状态徽标：抓取中 / 下载中 / 已暂停 / 已完成 / 已取消 / 已撤回 / 失败
  - 四个计数：文章 X/N · 图片 n 张 · 视频 m 个 · 累计 xx.x MB
  - 当前动作行：「正在处理第 7 篇：〈笔记标题〉」（列表页跳过标题时显示笔记 ID）
  - 失败行（F10 非零时显示）：「失败 2 篇」
  - 三按钮：暂停/恢复（互斥切换）、取消、撤回（撤回始终可见；运行中点撤回 = 先取消再删）
- 完成后：汇总 + 文件夹路径 + [撤回] 按钮。

## 6. 验收标准

1. 输入 `1504334302` 启动后，所有文件平铺落在 `<root>/1504334302/` 下（无笔记子目录，文件名带笔记 ID 前缀，无重名冲突）。
2. 全程抓包/日志确认同一时刻最多 1 个 HTTP 请求（串行红线）。
3. 进度面板四个计数与实际落盘文件数、`du` 字节数一致（±1MB 取整误差内）。
4. 暂停后当前文件完成即停、恢复后继续且不重复下载已完成文件。
5. 取消保留文件；撤回后 `<用户ID>/` 目录不存在（二次确认后）。
6. 断网/单篇 404：任务不死，计失败继续下一篇；连续限流触发退避并最终停止且有文案。
7. `tools/dev.sh build` 通过；Controller/状态机 JVM 单测通过。
