# 设备身份伪装调研（2026-10-24）

本机身份基线：HONOR AAK-AN00 / HNAAK / Android 17 / MagicOS 11.0.0.109 / fingerprint `HONOR/AAK-AN00/HNAAK:17/HONORAAK-AN00/11DLDLD109SP9C00E109:user/release-keys` / flavor magic-user。

## 身份 prop 组表（改哪个=改什么）
- ro.product.model(+odm.model)｜机型名｜多分区同名需同步
- ro.product.device(+odm.device)｜设备代号｜与 model 配对
- ro.build.fingerprint(+ro.honor.build.fingerprint)｜机型+版本一体指纹｜**OTA 匹配+Play Integrity 双红线**
- ro.build.flavor(magic-user)｜产品线标志，改它易穿帮
- version.incremental / display.id｜OTA 红线
- fingerprintName(HONOR-Z252)｜内部指纹代号，改 model 常需配套
- board/hardwareversion｜硬件绑定，跨 SoC 穿帮
- vendor.*(qti/sun)｜SoC 身份，**不动**
- cuptsm(HONORPAY|ESE)｜钱包 SE 硬件身份，动=断支付，否决
- 一致性原则：app 读 MODEL+DEVICE+FINGERPRINT，只改一处=自相矛盾比不改更危险

## 场景三档
a. **游戏白名单**：白名单按 model+device+fingerprint 三件匹配；三件必须同源真机官方值（勿手拼）；fingerprint 双红线=默认拒、显式放行才行；伪装后需清游戏数据重登（服务端按机型下发）
b. **荣耀内部功能门**：实测**未见按 model 下发的门**——msc.* 门是内置默认值非运行时比对；正路=直接翻 msc.*（见 11 号文件），伪装 model 大概率无效且有云控校验风险；同 SoC 高配兄弟机型(Pro/Ultra) fingerprintName 级伪装=待测不列方案
c. **兼容性伪装**：仅适用「老 app 不识别新机型名」场景，改 model 一件即可指纹不动；银行/支付/政务一律不伪装（设备指纹+服务端风控，识破=交易限制/封设备）

## 红线
OTA 错配变砖级（fingerprint/incremental/SP/build.date）；Play Integrity 连锁；荣耀云/查找设备/钱包重绑；会话层试出的值须固化进 system.prop 否则重启回真身、身份哈希突变更醒目；临时 root 环境伪装致 OTA 误匹配=自送 root。

## 结论
可放心做=单件 model 兼容性伪装；游戏三件套可行但需放行+官方值；功能解锁走 msc.* 不走伪装；支付场景一律不伪装。
