# 43-验证剧本：B 层 22 项 resetprop 门 + ★候选 一次 root 会话批量实证（2026-10-24）

**44 号实测修订**：本机 `settings list/put` 走 binder 会事务失败——**所有 settings 读写一律改用 `su -c 'content query/--uri content://settings/<table> --where "name=\\'key\\'"'` 与 `content insert/update` 路径**；相机 ★ 已由 44 号 HAL dump 部分定案（仅 LUT 可真开，见 24 号修订），P4 相机组相应收缩。

**性质**：纯调研设计文档，本文档本身不改任何设备状态。目标读者=未来执行验证的 agent/人（Re:荣耀 功能开关前置）。
**输入**：research/33-特性门总表.md B 层 22 项 + ★候选（相机 6 门/双 5G/DP PC/桌面动画档/协同档位/opta-optb）；基线参考 research/raw-getprop-20261024.txt；产物去向 28 号规格书 ToolSwitchTable。
**核心约束**：resetprop 属会话层（当次开机生效、重启即回）。一切验证在**单次 root 会话**内完成「快照→改→验→记→回滚」闭环，不做固化（不写 /data/adb 服务脚本）。

---

## 0. 前提与总则

- root 在场（KSU/Magisk/APatch 均可）；`resetprop` / `restoreprop` 可用（`which resetprop` 先验）。
- **提权预算**：验证会话独立开一次 su，不与 DIRTY 联动操作（刷模块/改系统分区）共用会话——DIRTY 通道按既有协议须保持干净，别把提权审批预算烧在只读性质的验证上。若验证会话已发生 DIRTY 联动，记录进 verdict.jsonl 的 note 字段。
- 相机门失败=相机 FC（重启级恢复）；opta/optb 影响面未知——两者单列（见 §3）。
- 所有 resetprop 写后**立即 getprop 回读**，回读≠目标值直接判 `no_effect`（部分 prop 由系统服务回写守护）。
- 档位型 prop（显示健康组/协同组/桌面动画档）**只上探一档、不连跳**；语义不明的（na​vi_extend/smallwindow）只记录不改。

## 1. 会话流程骨架（每步精确命令）

```
### P0 前置快照（约 3 min，全程 su 一次）
mkdir -p /data/local/tmp/verify43 research/verification
su -c 'getprop > research/verification/baseline-getprop.txt'          # 全量 prop
su -c 'settings list system  > research/verification/baseline-system.txt'
su -c 'settings list secure  > research/verification/baseline-secure.txt'
su -c 'settings list global  > research/verification/baseline-global.txt'
# 基线核对：对本文涉及 prop 逐条 grep 现值，写入 verdict 初始行

### P1 显示/桌面类（低风险先做）
# 逐项循环：改→触发→记录→回滚
su -c 'resetprop msc.launcher.unlock_animation_level 1'   # 例：桌面动画档
#   触发：回桌面滑一页、开一个 app 返回，观察动画变化（录屏 3s）
su -c 'resetprop msc.launcher.unlock_animation_level 0'   # 或 restoreprop 恢复原值
# 桌面类改后需重启 SystemUI/Launcher 才可能生效：
su -c 'killall com.android.launcher' 2>/dev/null || su -c 'am force-stop <launcher包>'

### P2 网络/系统类（中风险）
su -c 'resetprop msc.config.dual_5g_show_switch true'
#   触发：打开 设置>移动网络，看"双卡 5G"开关是否出现（getprop+截图双证据）
su -c 'resetprop msc.settings.support_5g_mode true'
#   触发：同上页看 5G 网络模式项（与 A2 show_5g_switch 成对核）
su -c 'resetprop msc.config.dp_pc_mode true'
#   触发：插 DP/Type-C 底座或 cast 设置页，看"电脑模式"入口
su -c 'resetprop msc.config.watermark true'
#   触发：相机水印设置页（与 msc.camera.watermark 呼应）

### P3 显示性能/档位组（上探一档）
su -c 'resetprop magic.config.enable_egl_cpu_throttle 0'
su -c 'setprop debug.gui.syncMode.eglCpuTrottling.enable false'   # 成对
su -c 'resetprop persist.sys.hn_screen_freq 3'            # 现 2→3
su -c 'resetprop persist.sys.hn.forcedark_policy 0'       # 语义验证：0/2 对照
su -c 'resetprop persist.bt.max.a2dp.connections 3'       # 需连 2 台 BT 验证
# 显示健康档位组（highfrequencypwm=13 等）：只读记录，不推荐改（33 号 B 层原文）

### P4 相机类（★一次一个，失败立即回滚+强杀相机）
# 顺序按崩溃风险从低到高：
for p in livephoto_enable video_movie_mode watermark honor_watermark \
         gesture_recognition support_720p_21_9 underwater; do
  su -c "resetprop msc.camera.$p true"
  su -c 'am start -a android.media.action.STILL_IMAGE_CAMERA'   # 冷启相机
  # 观察模式条/设置页是否出现对应项（uiautomator dump 或截图）
  su -c "resetprop msc.camera.$p false"                        # 回滚原值
done
# 高危单独做：dual.video_capbility_switch（编码超载）→ 改后录 10s 双景视频看发热/掉帧
# 4k_video_limit_duration：改后看录像剩余时长提示（判据：UI 显示的限时数字）

### P5 opta/optb 总门（单独会话，放最后）
su -c 'resetprop msc.config.opta <候选值>'    # 候选取值先反查 32 号报告来源
su -c 'resetprop msc.config.optb <候选值>'
# 触发：重启 SystemUI（su -c 'killall com.android.systemui'）后逐页扫设置
# 回滚：restoreprop msc.config.opta / msc.config.optb；若页面异常→重启

### P6 收尾
diff 基线 getprop → 确认全部还原；残留差异逐条 restoreprop
su -c 'settings put ... '（如有 settings 被联动改，按三表备份恢复）
# 最终：重启一次 = 双保险（会话层本就重启即回）
```

**排序原则**：显示/桌面（低）→ 网络/系统（中）→ 显示性能档位（中）→ 相机（一次一个）→ 协同档位组（高危，建议并入 opta 会话或单独）→ opta/optb 总门（压轴单独会话）。协同组（multiscreen.collaboration=3→4 等）越级可崩协同服务，若做则同 opta 会话、先备份 `dumpsys activity services | grep -i collaboration`。

## 2. 单项验证卡模板

每项一行卡，复制使用（yaml 块嵌入 md）：

```yaml
id: <B层序号或★名>
prop: msc.camera.livephoto_enable          # 或 persist.*/magic.*
原值: false                                  # 基线 grep 所得
改值: true
分组: P4-相机                                # P1~P5
预期现象: 相机模式条出现"实况"入口
验证动作: am start 相机 → uiautomator dump | grep -i live；截图 research/verification/<id>.png
回读判据: getprop 值==改值
回滚: resetprop <prop> <原值>（或 restoreprop）
失败现象记录位: verdict.jsonl 的 result=no_effect|fc|silent + evidence=dropbox/tombstone 路径或截图
关联: 33 号表行号 / 24 号 APK 键位 / 28 号 ToolSwitchTable 会话层分区
```

失败现象分类：`verified`（现象出现+回读通过）｜`no_effect`（回读通过但 UI 无变化=死键或另有门）｜`rewritten`（回读被守护进程回写）｜`fc`（应用崩溃→查 `/data/tombstones/` 与 `dumpsys dropbox --print` 最近条目）｜`untestable`（缺硬件/缺双卡等）。

## 3. 风险控制

1. **相机门铁律**：一次一个 prop；每验一项立即回滚再下一项；相机 FC → `am force-stop 相机包` + restoreprop；连续 2 次 FC → 本组中止，剩余标 `deferred`。相机崩溃即重启级，不追连跳。
2. **opta/optb 总门**：单独会话最后做；改前记录 `msc.sys.country` 现值；只动一个（opta 或 optb），另一个不动以保留对照；异常立即 restoreprop + 重启 SystemUI；极端情况重启手机（会话层自动全回）。
3. **档案型 prop 不改**：hyperhold.swapsize、enable_iaware（33 号已标不推荐）、显示健康档位组只读记录。
4. **DIRTY 联动**：本验证全程 resetprop（内存态），不改 /system、/data/adb、不刷模块——不触发 DIRTY 通道；若工具链要求验证会话前置 probe，复用 28 号 F3 活性卡单发拼链，不额外开 su 面板操作。
5. **中断恢复**：会话意外中断→重启即全回（会话层天然安全网）；verdict.jsonl 已写行不丢。

## 4. 记录格式：verdict.jsonl

落 `research/verification/verdict.jsonl`，一行一 JSON：

```json
{"prop":"msc.config.dp_pc_mode","value":"true","result":"verified","evidence":"dp_pc_entry.png;getprop==true","ts":"2026-10-24T22:05:11+08:00","card":"P2","note":""}
```

字段：`prop`/`value`（改值）/`result`（§2 五分类）/`evidence`（文件名列表，勿内联大文本）/`ts`（ISO8601）/`card`（分组）/`note`（失败细节/DIRTY 标记）。终态另汇总 `summary.md`（verified N / no_effect M / ...），FeatureCatalog 未来直接引 jsonl 的 `result=="verified"` 集合。

## 5. 与 app 的衔接（28 号规格书）

28 号 §4 明确「resetprop 会话层全数排除，另设只读说明区」。验证通过后的开区路径：
1. **第一档（零改动）**：只读说明区扩容——把 verified 项以静态卡片呈现（prop/现值/预期/需 root+resetprop 提示），不提供执行。
2. **第二档（开区）**：ToolSwitchTable 新增 `sessionLayer` 分区，Entry 增加 `kind="resetprop"` 与 `needsRestart`（提示"重启后失效"）；ToolExecutor.verify 的回读判据从 `settings get` 换 `getprop`。执行前提=app 侧 root 在场 + 用户确认会话层性质。
3. **第三档（固化，默认不做）**：如未来要求重启保持，才引入 /data/adb 服务脚本（属 DIRTY 面，须单独评估）。
4. 排除区将来开区顺序建议：桌面动画档（低风险 verified 优先）→ dual_5g/dp_pc/watermark → 相机门组（逐门灰度+FC 自动回滚逻辑）→ opta/optb 永不进 app（影响面大，仅研究记录）。
